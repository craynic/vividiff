# vividiff 项目计划书

状态：M0–M5 v0.1 实现与 Windows 自动化验收已完成；实际验证及人工验收边界见 [STATUS.md](STATUS.md)，架构调整见 [ARCHITECTURE.md](ARCHITECTURE.md)  
首发平台：Windows；架构保持跨平台  
目标版本：v0.1 本地评审 MVP

## 1. 产品定位

vividiff 是面向开发者与 Code Agent 协作的本地代码对比与批注工具，不是 VCS 客户端，也不是代码托管或合并管理工具。

核心分工：Code Agent 在 vividiff 之外负责代码修改及所需的 VCS 操作；vividiff 负责呈现具体改动、承载用户批注并将反馈交还 Agent。用户只需关注“改了什么、哪里有问题”，不需要在工具中操作仓库工作流。

以 VCS 不同版本之间的对比为主要场景，首要支持 Git；VCS 仅作为只读内容来源。支持用户在同一评审中自由切换对比版本、添加批注并提交评审结果，让发起评审的 Agent 能够可靠读取反馈。

普通两文件对比作为次要入口，复用内容快照、差异展示和批注能力。

界面以改动内容为中心：Agent 发起后直接进入 diff；版本选择是辅助浏览能力，不发展为分支管理、提交管理或仓库操作面板。

## 2. 首版目标与永久产品边界

### 2.1 必须实现

- Windows 桌面应用，采用 Tauri 2。
- 界面多语言支持：首版内置英文（en）和简体中文（zh-CN），界面默认跟随系统，支持手动选择及偏好持久化；通过外部语言文件增加语言选项，英文仅作为基准及降级语言，缺失翻译键回退英文。
- 本地 Git 仓库评审：提交、分支、标签、暂存区、工作区。
- 左右版本自由选择，支持交换、刷新和返回历史对比。
- 提供直接对比；另提供明确标注的共同祖先（merge-base）对比模式，仅用于确定对比基准，不执行合并。
- 变更文件列表、统一／并排 diff、语法高亮、变更跳转。
- 文件级、单行、多行批注；编辑、删除、解决和重新打开批注。
- 评审会话及批注本地持久化。
- 用户明确点击“完成评审”后，生成 Agent 可读取的结构化结果。
- MCP stdio 接口，以及 CLI 和可供 Agent 使用的 Skill 示例。
- VCS 插件协议、Git 插件、语言高亮资源插件及本地安装能力。
- 普通两文件只读对比。

### 2.2 永久不做

以下是产品职责边界，不是延后实现的功能；同样约束 UI、CLI、MCP 和插件协议：

- VCS 写操作及仓库管理：创建／切换／删除分支、暂存、提交、回退、变基、合并、冲突解决、stash、fetch、pull、push 等。
- PR/MR 创建、导入、管理、审批、合并及托管平台评论同步；不接入托管平台账户体系。
- 修改源文件、应用补丁或建议、自动修复代码。
- 通过插件或内置命令执行入口绕过上述边界。

这些工作由 Code Agent 或用户在外部工具中完成，vividiff 不负责调度或代理执行。切换对比版本只读取内容，不能触发 checkout 或改变工作区／暂存区。工具只写入自身的配置、快照、批注及评审结果，不修改被对比的源文件或仓库状态。

### 2.3 首版暂不做

- 多人在线协作、云端账户和云同步。
- 插件市场、自动更新、任意前端 UI 插件。
- 将第三方可执行插件作为安全代码运行的完整沙箱。
- Git 以外的生产级 VCS 插件；首版通过测试适配器验证可扩展性。
- 图片、音视频和二进制文件的内容差异分析。

## 3. 用户流程

### 3.1 手动评审

1. 打开本地仓库，选择或创建评审。
2. 选择对比模式及左右版本。
3. 浏览文件与差异，添加批注。
4. 按需要切换版本或刷新工作区，历史批注继续保留。
5. 查看全部批注，明确完成评审。
6. 后续仍可查看评审结果及原始代码上下文。

### 3.2 Agent 发起评审

1. Agent 通过 MCP 或 CLI 提交仓库、初始版本、标题及评审说明。
2. 服务创建持久化会话并返回 reviewId，启动或唤起桌面应用。
3. 用户直接查看具体改动，可自由切换对比版本并添加批注，无需执行 VCS 操作。
4. 用户完成评审，服务保存不可变的本次结果快照。
5. Agent 查询完成状态，读取对应结果与批注上下文。
6. 如需修改，Agent 在 vividiff 之外修改代码并执行所需 VCS 操作，再发起下一轮对比；vividiff 仅展示和收集反馈。

协议不依赖长时间挂起的单个 MCP 请求。桌面窗口关闭、Agent 断开或进程重启后，已保存的会话与结果仍可读取。

## 4. 技术方案

| 模块 | 初步选择 | 说明 |
| --- | --- | --- |
| 桌面容器 | Tauri 2 | Windows 优先，避免核心依赖 Windows 专用 API |
| 界面 | React + TypeScript | 文件树、版本选择、diff、批注和会话界面 |
| 界面国际化 | i18next + react-i18next | 声明式翻译资源、运行时语言切换，日期／数字使用 Intl 格式化 |
| 评审服务 | Rust 本地服务进程 | 会话、快照、插件管理、存储和结构化接口 |
| 存储 | SQLite + 本地快照文件 | SQLite 保存索引与事务状态，快照文件保存内容 |
| Git | 独立 Git 插件调用本机 Git | 参数化调用，禁止 shell 字符串拼接 |
| 差异计算 | 核心统一计算 | 具体库在 M0 验证，VCS 原生结果可用于辅助识别文件变更 |
| 高亮 | Shiki + TextMate grammar | 声明式语言包，失败降级为纯文本 |
| Agent 接入 | MCP stdio + CLI | 共用评审服务，不另建一套状态 |
| 插件通信 | 版本化 JSON-RPC over stdio | 请求 ID、超时、取消、错误码和能力协商 |

上述为拟定方案。M0 先验证服务生命周期、Tauri 打包、diff 渲染和插件进程通信，再冻结关键接口。

### 4.1 进程与职责

```text
Tauri 桌面应用 ──────┐
CLI ────────────────┼── 本地评审服务 ── SQLite / 内容快照
MCP stdio 桥接进程 ─┘          │
                              └── VCS 插件进程 ── 本地仓库

语言包 / 主题包 ── 高亮引擎 ── diff 界面
```

- 桌面、CLI 和 MCP 复用统一业务逻辑；评审服务统一协调写入。
- MCP 桥接可按需启动服务；发起评审可请求唤起桌面窗口。
- 服务端接口使用 loopback + 每用户随机凭据；不得监听公网地址。
- 不将本地接口开放给任意网页，校验认证和来源；生产版不使用宽泛 CORS。
- 服务生命周期、单实例、凭据保存和异常退出恢复在 M0 验证。

### 4.2 界面多语言（i18n）

- 首版内置英文（`en`）和简体中文（`zh-CN`）。区分“界面语言选择”与“降级语言”：界面默认跟随系统，英文作为固定的基准及降级语言（fallback），不强制界面首次启动显示英文。
- 设置提供“跟随系统”和具体语言选项，保存用户偏好；显式选择优先于系统语言。“跟随系统”按系统首选语言与已加载语言进行 locale 匹配，无匹配时才回退英文；不因单个翻译键缺失而切换整个界面语言。
- 支持通过外部 JSON 语言文件增加界面语言选项，无需修改代码或重新构建应用。用户将文件放入应用数据目录的 `locales/` 后，应用在启动或用户点击“重新加载语言”时校验并加载，自动更新语言选项。
- 每个语言文件包含 `schemaVersion`、`locale`、`nativeName` 和按功能命名空间组织的 `translations`；语言选项展示语言自称和 locale，便于识别。
- 外部语言文件允许只提供部分翻译。当前语言缺失的键、空值或不合法的条目逐键回退到内置英文；复数消息按完整键组校验，缺少所需形式或插值参数不一致时，整组使用英文及英文复数规则，避免混用规则。
- 内置英文是完整且不可被外部文件覆盖的基准资源。英文键完整性由自动化测试保障，不向用户展示内部翻译键。
- 已选择的语言文件被移除或无法加载时，界面回退英文并提示原因。重复 locale（包括与内置语言冲突）、无效元数据、JSON 解析失败或不支持的 schemaVersion 均明确报错，不静默覆盖已有语言。
- 手动选择保存在应用级偏好中，重启后恢复；切换语言即时更新应用管理的界面，不重载评审、不清空未保存的批注输入或改变当前对比。
- 所有应用自有界面文案统一使用翻译键，包括菜单、按钮、设置、空状态、提示、错误、批注状态和无障碍标签。操作系统管理的原生对话框文案遵循系统语言限制。
- 翻译按功能命名空间组织，支持插值与复数规则，不拼接自然语言句子。日期、时间、数字按 locale 展示；持久化数据使用与语言无关的格式。
- 后端及插件使用稳定错误码和结构化参数，由界面映射成本地化提示；未知错误显示本地化通用提示，原始诊断信息单独保留。
- 不翻译源代码、文件路径、分支／标签名、提交说明、用户批注及 Agent 提供的评审说明。
- MCP／CLI JSON 的字段名、枚举、错误码及结果标识保持稳定，不随界面语言变化；界面语言不影响批注锚点、diff 计算或评审结果语义。
- 界面翻译文件与“编程语言高亮包”是不同概念，使用独立目录和命名空间。语言文件只提供声明式文本，不运行脚本、不加载远端资源、不渲染任意 HTML；加载时限制文件大小并校验结构。
- 新增语言无需翻译完整即可使用，未提供的文案保持英文；官方内置语言需完成翻译与布局验收。首版不承诺尚未测试的 RTL 语言支持。

语言文件示例（翻译键仅作格式说明，实际键清单随开发维护）：

```json
{
  "schemaVersion": 1,
  "locale": "fr",
  "nativeName": "Français",
  "translations": {
    "common": {
      "cancel": "Annuler"
    }
  }
}
```

加载后设置中出现 `Français (fr)`；选择后 `common.cancel` 使用法文，其余未提供的文案使用内置英文。

## 5. 插件设计

### 5.1 VCS 插件

VCS 插件的职责是提供只读版本与内容，不是提供 VCS 操作。Git 作为内置插件，但必须遵循与外部插件相同的协议；协议永久不提供写仓库、合并、冲突解决或执行任意 VCS 命令的接口。

最小能力接口：

- `detectRepository`：检测仓库及根目录。
- `getCapabilities`：声明分支、标签、暂存区、工作区、merge-base 等能力。
- `listRevisions`：分页列出可选版本及展示信息。
- `resolveRevision`：将用户选择解析为稳定版本标识。
- `listChanges`：列出两个版本之间的文件变化。
- `readFile`：读取指定版本的文件内容与元数据。
- `getMergeBase`：可选能力，用于共同祖先对比。

核心不能假定所有 VCS 都有 Git 暂存区或提交 SHA。界面按插件能力展示选项，版本标识由 provider 命名空间限定。

首版定义清单字段：插件 ID、版本、协议版本、支持平台、入口、能力和所需权限说明。支持本地目录安装、启用、禁用和错误诊断。

插件崩溃或超时不得导致整个应用退出。独立进程用于稳定性隔离，不宣称提供安全沙箱；第三方可执行插件需要用户明确确认信任，不自动执行仓库中声明的插件。

### 5.2 语言高亮与主题插件

- 语言包包含语言 ID、扩展名／文件名匹配、语法资源和依赖。
- 主题包只包含声明式颜色配置。
- 首版不允许语言包注入任意 JavaScript 或 UI 代码。
- 按需加载，设置资源大小、处理超时和依赖校验。
- 高亮不参与批注定位与 diff 正确性，失败时退回纯文本。
- 本地插件优先级明确，ID 冲突和缺失依赖应有可读错误。

## 6. 会话、版本与批注模型

### 6.1 主要实体

- `ReviewSession`：仓库／文件来源、标题、说明、状态与创建来源。
- `Comparison`：对比模式、用户选择、解析后的左右快照。
- `ContentSnapshot`：稳定版本标识、文件内容引用、内容摘要和编码信息。
- `Comment`：正文、状态、创建时间与原始锚点。
- `CommentPlacement`：某条批注在另一对比中的定位结果，不覆盖原始锚点。
- `ReviewSubmission`：用户完成评审时生成的不可变结果及结果序号。

### 6.2 版本切换原则

- 评审会话与当前显示的对比分离；切换对比不删除批注。
- 分支和标签进入对比时解析为稳定版本，不能仅存名称。
- 工作区、暂存区及普通文件内容进入对比时冻结为快照；刷新生成新快照。
- 批注必须指向用户实际看到的快照，而不是读取批注时的最新内容。
- 活跃工作区扫描可能遇到并发编辑；检测到变化时重试或提示，不宣称跨文件扫描天然原子化。
- 至少保留所有被批注及提交结果引用的内容；删除会话前不回收仍被引用的快照。

批注锚点包含 provider、comparisonId、左右侧、文件路径、旧／新路径、行范围、内容摘要和必要代码上下文。

### 6.3 跨版本展示批注

1. 原始快照：精确展示。
2. 其他快照：通过重命名信息、行映射和代码上下文尝试定位。
3. 只有唯一且可靠的映射才附着到新位置，并注明来自其他版本。
4. 存在歧义或无法定位时，显示为“其他版本的批注”，可跳回原始上下文。

首版优先保证“不错误定位”，不追求所有批注自动迁移。

### 6.4 完成与重新评审

- 状态：草稿 → 评审中 → 已完成；另支持已取消。
- “完成评审”是用户的明确动作；关闭窗口不等于完成。
- 首版 Agent 公共接口不能代替用户完成评审。
- 完成时事务性保存结果：包括评审范围、曾对比的版本、所有批注及其状态，不只包含当前屏幕上的批注。
- 无批注的完成结果也是有效结果；“已完成”仅代表完成流程，不自动表示代码获准合并。
- 已完成会话默认只读；用户重新打开后可继续评审，再次完成生成新的结果序号，旧结果保留。

## 7. Agent 接口

拟定 MCP 工具：

| 工具 | 功能 |
| --- | --- |
| `review_create` | 创建／按幂等键复用评审，返回 reviewId 和打开信息 |
| `review_open` | 唤起桌面应用中的指定评审 |
| `review_status` | 返回会话状态、最新提交序号及更新时间 |
| `review_comments` | 分页读取当前批注，支持状态过滤；明确标识是否为草稿 |
| `review_result` | 读取指定或最新已完成结果；未完成时明确返回尚无结果 |

CLI 提供对应子命令，支持 `--json`。可提供带超时与取消的 `wait` 命令，超时只结束等待，不取消评审。

结果至少包含：schemaVersion、reviewId、submissionId、结果序号、完成时间、仓库标识、对比版本、批注正文、文件路径、左右侧、行范围、原始代码上下文及解决状态。

Skill 示例说明：如何发起、如何等待／恢复查询、如何读取结果，并提醒 Agent 将批注视为用户反馈而非自动执行的命令。示例不得绑定单一厂商的 Agent。

## 8. 里程碑

### M0：架构验证与工程基础

交付：
- Tauri + React + TypeScript + Rust 工程骨架。
- i18n 基础设施、英文基准／降级资源与简体中文资源、系统语言匹配、语言设置及持久化。
- 外部语言文件格式、目录扫描、重新加载、校验及逐键英文回退；后续功能同步维护英文键清单和内置中文翻译。
- 开发、检查、测试、打包脚本和 Windows 环境说明。
- 本地服务与桌面／CLI 最小通信验证。
- VCS 插件握手、启动和退出验证。
- diff 渲染、高亮、长文件虚拟滚动技术验证。
- 架构决策记录及协议 v0 草案。

验收：
- Windows 上能启动桌面应用并打包安装运行。
- 多入口启动不会产生互相冲突的服务实例。
- 界面能显示固定测试内容的 diff。
- 首次启动默认跟随系统：系统语言匹配已加载语言时使用该语言，无匹配时回退英文；可即时手动切换或恢复跟随系统，并在重启后恢复偏好。
- 放入仅包含部分翻译的测试语言文件后，无需重新构建即可出现新语言选项，缺失键显示英文；文件损坏、移除或 locale 冲突时可安全回退或拒绝加载。
- 完成核心依赖许可证检查；记录性能基准环境与测试样本。

### M1：Git 对比闭环

交付：
- Git 内置插件及仓库选择。
- 分支、标签、提交选择；暂存区和工作区对比。
- 直接对比与 merge-base 模式。
- 文件列表、统一／并排 diff、基础高亮和变更导航。
- 内容快照与历史对比记录。

验收：
- 对测试仓库中的提交、暂存区和工作区得到符合预期的差异。
- 覆盖新增、删除、修改、重命名、未跟踪文件与空文件。
- 中文／空格路径、CRLF／LF、无结尾换行、非 UTF-8 内容有明确处理。
- 空仓库、无共同祖先、二进制文件、子模块、符号链接和超大文件不会导致崩溃；不支持的情况明确提示。
- 可以自由切换左右版本，旧快照保持稳定。
- 切换版本和浏览差异不改变 HEAD、分支引用、暂存区或工作区内容；界面没有仓库写操作入口。

### M2：批注与评审会话

交付：
- SQLite 数据模型与迁移机制。
- 文件级、单行、多行批注及状态管理。
- 会话列表、恢复、完成、取消和重新打开。
- 跨版本批注展示与原始上下文跳转。
- 不可变提交结果及 JSON 导出。

验收：
- 重启应用后会话、批注与原始代码仍可恢复。
- 切换版本、刷新工作区、文件重命名和删除不会丢失批注。
- 定位不确定时不会静默把批注挂到错误行。
- 完成结果包含所有版本上的批注；无批注也能完成。
- 重新打开后再次提交，不改变以前提交的结果。

### M3：Agent 评审闭环

交付：
- MCP stdio 桥接与评审工具。
- CLI 创建、查询、打开、读取及等待命令。
- 通用 Skill 示例和 MCP 配置文档。
- 幂等创建、超时、断线恢复和结构化错误。

验收：
- 在至少一个真实 Code Agent 客户端跑通“发起 → 用户评审 → 完成 → Agent 读取”。
- 用户更换对比版本后，Agent 能知道每条批注实际针对哪个版本。
- Agent 或桌面应用中途退出，恢复后仍可读取已保存状态及结果。
- 重试创建不会重复产生会话；结果序号可用于去重消费。
- MCP stdout 仅输出协议消息，日志走 stderr 或日志文件。
- Agent 在工具之外完成修改与 VCS 操作后可发起复评；vividiff 的 MCP／CLI 不提供代码修改或仓库操作接口。

### M4：插件扩展能力与普通文件对比

交付：
- 插件本地安装、启停、兼容性检查和诊断界面。
- VCS 插件开发文档、示例和协议测试套件。
- 语言包和主题包的安装、加载与失败降级。
- 普通两文件对比入口，复用快照、批注和评审结果。

验收：
- 不修改核心代码即可加载一个测试 VCS provider，证明接口没有写死 Git。
- 从外部目录加载自定义语言包和主题。
- 插件崩溃、超时、协议不兼容、依赖缺失均能给出清晰错误。
- 普通文件发生后续变化，不会改变已保存批注的原始上下文。

### M5：稳定性、打包与 v0.1 验收

交付：
- Windows 安装包、使用文档、排障说明及已知限制。
- 简体中文／英文全界面文案及布局验收，翻译键与插值参数自动检查。
- 关键路径自动化测试、性能回归和崩溃恢复测试。
- 本地接口与插件权限安全检查。
- M5 仅验收 Windows；不包含 macOS／Linux 的构建、测试或打包验证。

验收：
- 新环境能按文档安装、检测 Git 并完成一次完整评审。
- 完成第 9 节的核心测试场景，无已知批注丢失或错误归属问题。
- 两种界面语言均跑通完整评审流程；切换语言不丢失批注草稿，不改变快照或 Agent 结构化结果。
- 大仓库／大文件有进度、取消和降级机制，不因高亮阻塞整个界面。
- 安装包明确标识签名状态；正式对外发行前单独确认代码签名安排。

## 9. 测试与质量门槛

### 正确性

- 使用可重建的 Git 测试仓库验证版本解析、merge-base、暂存区和工作区语义。
- 增删改、重命名、复制、文件类型变化、大小写路径和特殊字符路径。
- 连续编辑工作区、分支移动、仓库删除及原始提交不可读取。
- 重复代码上下文、跨版本行移动和删除行批注，验证歧义降级。
- 数据库迁移、服务意外退出、完成结果事务性和快照引用完整性。

### 协议与安全

- 插件和 Agent 接口的版本兼容、分页、取消、幂等和错误码。
- 不将仓库内容、批注正文或插件输出当作 HTML／脚本执行。
- 路径遍历、恶意版本参数、插件包路径逃逸和未认证本地请求。
- Git 只读操作禁止触发外部 diff、textconv 或仓库配置的可执行扩展，避免隐式写入仓库状态。
- 对比前后核对 HEAD、分支引用、暂存区和工作区内容；验证所有入口均遵守只读源数据的产品边界。
- 快照与批注留在本机；提供会话删除入口和数据存储位置说明。

### 国际化

- 检查内置英文键完整性、内置中文翻译覆盖、插值参数一致性、复数规则，以及外部语言缺失键／空值／非法条目的英文回退。
- 覆盖首次启动跟随系统、已加载语言的 locale 匹配、无匹配时英文回退、手动选择优先、恢复跟随系统、偏好恢复及选中语言不可用时的英文回退。
- 覆盖外部语言文件发现、重新加载、新增选项、文件移除／损坏、重复 locale、schemaVersion 不兼容及资源大小限制；验证无需重新构建应用即可增加语言。
- 检查长文案、窗口缩放、菜单、提示和无障碍标签；不因翻译造成关键操作被裁切或遮挡。
- 在批注编辑中切换语言，验证输入、选区、当前版本与滚动位置保持。
- 验证日期／数字本地化展示与持久化格式分离，MCP／CLI JSON 不受界面语言影响。

### 性能

- M0 建立参考机器、固定样本和可重复测量脚本。
- 小仓库交互与版本切换优先保持及时响应。
- 以千级变更文件和十万行级文本文件作为压力样本，使用懒加载、虚拟列表、高亮限制和可取消计算。
- 具体耗时与内存预算在 M0 实测后确定，不以未测数字作为发布承诺。

## 10. 实施顺序与阶段检查点

主线：M0 → M1 → M2 → M3 → M4 → M5。

- M1 完成：得到可实际使用的 Git diff 查看器。
- M2 完成：得到可独立使用的本地评审工具。
- M3 完成：核心产品目标达成，可邀请少量用户试用。
- M4 完成：扩展能力与次要场景补齐。
- M5 完成：发布 v0.1。

插件协议在 M0 设计、M1 使用，M4 只补齐用户安装与开发者体验，不能拖到 M4 才把 Git 从核心拆出来。

每个里程碑完成时更新实现状态、演示步骤、测试结果、已知问题和下一阶段风险。时间估算在 M0 验证后补充，先以交付物及验收条件控制范围。

## 11. 主要风险及应对

| 风险 | 应对 |
| --- | --- |
| 切换版本后批注错位 | 原始快照不可变；派生定位不覆盖原始锚点；歧义明确降级 |
| 工作区持续变化 | 冻结实际展示内容；检测扫描期间变化；刷新生成新快照 |
| Tauri／WebView 大 diff 性能 | M0 先验证；虚拟滚动、按需加载、后台高亮与降级 |
| 插件设计过重 | 首版仅 VCS 可执行插件、声明式语言／主题包，不做通用 UI 插件 |
| 本地服务生命周期复杂 | M0 验证单实例、自动启动、认证及异常退出恢复 |
| 第三方插件获得本机权限 | 明确信任确认，不自动执行仓库插件，不把进程隔离宣传为沙箱 |
| Windows 路径与进程行为差异 | 参数化进程调用，覆盖 Unicode、长路径、大小写与取消行为 |
| 快照占用磁盘 | 内容寻址去重，明确引用关系，支持会话删除后安全回收 |
| 产品偏离对比职责 | 优先完成 M3；后续只扩展内容来源、差异展示和反馈能力，VCS 写操作、PR/MR 管理及代码编辑永久排除 |

## 12. 后续候选方向

- macOS／Linux 适配、构建、测试与桌面发行：后续独立规划，不属于 M5；当前仅在架构设计中保持跨平台边界。
- SVN、Mercurial 等 VCS 插件。
- Tree-sitter 等结构化高亮／语法差异引擎。
- 图片 diff、更丰富的差异导航与批注展示。
- 多轮对比与反馈追踪；代码修复始终由 Agent 在工具之外完成。
- 插件分发、签名与自动更新。

以上均不属于 v0.1 的验收范围，且必须遵守第 2.2 节的永久产品边界。
